# Project Glossary

| Name                                   | Aliases                                  | Description                                                                                                                                                                                              |
|----------------------------------------|------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Design System                          | DS, UI                                   | Project design system located in `packages/ui`.                                                                                                                                                          |
| Manager                                | manager app, app manager                 | Product application consuming Powercoach UI, served locally on port 3000. During the revamp, its working directory is `apps/manager-revamp`, but role artifacts should call the product `manager`.      |
| Manager Working Directory              | manager workdir                          | Current implementation directory for manager delivery: `apps/manager-revamp`.                                                                                                                           |
| Storybook                              | SB                                       | Powercoach UI presentation and inspection surface, served locally on port 6006.                                                                                                                          |
| Powercoach UI                          | powercoach-ui, @powercoach/ui            | Public design-system package consumed by the manager. Manager agents treat it as a public dependency, not as source to copy or hack.                                                                 |
| Base UI                                | BaseUI                                   | Primitive library used as the reference for Powercoach UI APIs, behavior, and accessibility.                                                                                                             |
| Foreground                             | foreground, FG                           | Semantic color for primary content and contrasting borders. It is dark against Background by default and becomes light when dark mode inverts the Foreground/Background pair.                            |
| Background                             | background, BG                           | Semantic base surface color. It is light behind Foreground by default and becomes dark when dark mode inverts the Foreground/Background pair.                                                            |
| Dark mode                              | dark-mode, dark                          | Dark mode is handled with a `dark` CSS-based toggle on the `body` element, allowing the interface theme to switch globally by applying or removing dark-mode token colors.                               |
| Light mode                             | light-mode, light                        | Light mode is handled with a `light` CSS-based toggle on the `body` element, allowing the interface theme to switch globally by applying or removing light-mode token colors. Light is the default mode. |
| Brand Reveal                           | Reveal, RevealAnimation                  | Named Powercoach UI animation. Its public behavior is defined only by `RevealAnimation.md`.                                                                                                              |
| Animation Engine                       | engine                                   | Required PM decision for any intent that creates or changes animation behavior. Accepted values are `CSS` and `Motion`; agents must not infer or substitute the engine.                                  |
| Coss                                   | coss                                     | Legacy UI system to remove, with no compatibility requirement.                                                                                                                                           |
| Design System Delivery                 | ds-delivery, ds-deliv                    | Orchestration role that routes artifacts between dedicated design-system subagents.                                                                                                                      |
| Design System PO                       | ds-po                                    | Specification authoring role that questions the PM and writes the approved public spec.                                                                                                                  |
| Design System TDD                      | ds-tdd                                   | T(B)DD role that translates the approved spec or QA findings into a deliberately red executable contract.                                                                                                |
| Design System Dev                      | ds-dev                                   | Implementation role that makes the executable contract green and creates inspectable stories.                                                                                                            |
| Design System Dev Advice               | ds-dev-advice                            | Technical advice role used by ds-po before the spec is approved.                                                                                                                                        |
| Design System Dev PM Advice            | ds-dev-pm-advice                         | Free-form PM advice mode of ds-dev. It follows technical-advice rules without requiring the structured technical-question input artifact.                                                                |
| Design System Review                   | ds-review                                | Independent source-review role that checks implementation, tests, stories, coding style, and package conventions.                                                                                        |
| Design System QA                       | ds-qa                                    | Independent rendered-QA role that checks the approved spec in Storybook and the manager.                                                                                                                 |
| Manager Delivery                       | manager-delivery, mg-delivery, mg-deliv  | Orchestration role that routes artifacts between dedicated manager subagents and handles Design System dependency handoff.                                                                   |
| Manager PO                             | manager-po, mg-po, mg-spec, manager-spec | Product/specification role that questions the PM, writes approved manager specs, and emits Design System intents when UI capability is missing.                                            |
| Manager TDD                            | manager-tdd, mg-tdd                      | T(B)DD role that translates approved manager specs or corrections into manager executable tests.                                                                                                        |
| Manager Dev                            | manager-dev, mg-dev                      | PM advice, technical advice, and implementation role for manager work inside the current manager working directory.                                                                                      |
| Manager Dev PM Advice                  | manager-dev-pm-advice, mg-dev-pm-advice  | Free-form PM advice mode of mg-dev. It follows technical-advice rules without requiring the structured technical-question input artifact.                                                               |
| Manager Review                         | manager-review, mg-review                | Independent source-review role that checks manager implementation, tests, architecture, coding style, and public UI usage.                                                                              |
| Manager QA                             | manager-qa, mg-qa                        | Independent rendered-QA role that checks approved manager specs in the running manager.                                                                                                                 |
| Product Question                       | PQ, PQ-*                                 | Stable question ID emitted by a PO/spec authoring role when a product or PM decision is required before continuing specification authoring.                                                              |
| Spec Question                          | SQ, SQ-*                                 | Stable question ID emitted during QA when an observed behavior is outside the approved spec but may be useful enough to ask the PM whether the spec should change.                                       |
| Code Review Finding                    | CR, CR-*                                 | Stable finding ID emitted by a review role for source review issues. Corrections that address it must preserve the same ID.                                                                             |
| QA Finding                             | QA, QA-*                                 | Stable finding ID emitted by a rendered-QA role for approved spec behavior that is missing, wrong, or slopped in the running UI.                                                                         |
| Spec Revision Ticket                   | SR, SR-*                                 | Stable scope ticket emitted by a spec authoring role with a spec revision. It explains why the revision exists and bounds downstream work. `SR-*` is local to one spec.                                |
| Design System Intent Required          | DS Intent Required                       | Manager delivery artifact emitted when a manager feature needs missing public Powercoach UI capability before manager work can continue without hacks.                                                  |
| Linked SR Batch                        | linked batch, SR batch                   | Explicit PM or ds-delivery authorization to process several related `SR-*` tickets atomically in one delivery pass while keeping each ticket, spec, artifact, and traceability separate. If raw `SR-*` IDs repeat, identify tickets as `<spec-path>#SR-###`. |
| PM Visual Assets                       | visual assets, bug assets                | Local image or video paths provided by Yann in a PM intent or directed PM update to show a visual reference, bug, or regression evidence.                                                                |
| Use Case                               | UC, UC-*                                 | Public spec scenario describing expected user-facing behavior that ds-tdd translates into executable tests.                                                                                             |
| Example                                | EX, EX-*                                 | Public spec example showing consumer-facing usage that ds-dev must implement in Storybook for inspection.                                                                                               |
