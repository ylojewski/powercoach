# Manager Delivery Orchestration

## Roles

- `manager-po`: warm `$manager-po`, authoring mode.
- `manager-dev-advice`: warm `$manager-dev`, technical-advice mode.
- `manager-tdd`: warm `$manager-tdd`, test mode.
- `manager-dev`: `$manager-dev`, implementation mode, started after `Test Ready`.
- `manager-review`: independent `$manager-review`, started after `Implementation Ready`.
- `manager-qa`: independent `$manager-qa`, started after `Review Go`.

Reuse each role for corrections. Replace a role only when the platform reports that its live agent path, route, or thread is no longer available. This is a replacement of the same role, not a workflow restart.

Delivery is artifact-first. The latest validated artifact of each reached state and the active `Spec Revision Ticket` are the recovery source of truth. Do not send obsolete conversation, summaries, or interpreted history.

## Isolation

Delivery is the only router. If another role needs another role to act, it must return its normal artifact or `Blocked`.

If Delivery observes a non-delivery role contacting another role or thread, discard artifacts produced after that contact and recover once with the same envelope. If it repeats, return `Blocked`.

## Prompt Envelope

Use one exact mode line generated by Delivery:

```text
$skill-name
Mode: <authoring | technical-advice | test | implementation | source-review | qa>

<complete required artifact blocks>
```

Mode is read only from this top-level line.

The initial request uses:

```text
PM Intent
BEGIN PM INTENT
<verbatim product intent>
END PM INTENT
```

If the boundary is unclear, return `Awaiting PM`.

If the intent or a directed PM update contains local image or video paths, maintain one active block:

```text
PM Visual Assets
- /absolute/or/verbatim/path/to/asset
```

Include it in every prompt and require every role to copy it verbatim in returned artifacts.

## Canonical Envelopes

Do not omit a required block because a role is warm.

### Authoring

- Initial authoring to `manager-po`: complete `PM Intent`.
- Product-question answer to `manager-po`: complete previous `Product Questions` plus verbatim PM/user answers.
- Technical advice return to `manager-po`: complete previous `Technical Question For manager-dev` plus matching complete `Technical Manager Advice`.
- Accepted `Spec Questions` to `manager-po`: complete `Spec Questions` plus verbatim PM/user decision.

### Technical Advice

- Technical question to `manager-dev-advice`: exactly one complete `Technical Question For manager-dev`.

### Design System Dependency

When `manager-po` returns `Design System Intent Required`, stop the manager loop with `Awaiting Design System`.

Only `manager-delivery` may route the proposed DS intent to `design-system-delivery`. Do not let `manager-po`, `manager-dev`, `manager-tdd`, `manager-review`, or `manager-qa` launch DS work.

Resume manager delivery only after the PM/user or completed DS delivery provides the delivered UI capability or a replacement PM decision.

### Test

- Initial test to `manager-tdd`: complete `Feature Spec Ready` plus active `Spec Revision Ticket`.
- Review correction to `manager-tdd`: complete `Review Ko` projection owned by `manager-tdd`, latest complete `Test Ready`, plus active ticket.
- QA correction to `manager-tdd`: complete `QA Ko` plus active ticket.
- Accepted `SQ-*` correction to `manager-tdd`: corrected complete `Feature Spec Ready` with accepted `SQ-*` IDs in `Addresses`, plus replacement ticket.

### Implementation

- Initial implementation to `manager-dev`: complete `Test Ready` plus active ticket.
- Review correction to `manager-dev`: complete `Review Ko` projection owned by `manager-dev`, latest complete `Test Ready`, plus active ticket.
- QA correction to `manager-dev`: complete `QA Ko`, complete new `Test Ready`, plus active ticket.
- Accepted `SQ-*` correction to `manager-dev`: corrected complete `Test Ready`, plus replacement ticket.

### Source Review

- Initial review to `manager-review`: complete `Implementation Ready` plus active ticket.
- Review correction to `manager-review`: complete previous `Review Ko`, latest complete `Implementation Ready`, latest complete `Test Ready`, plus active ticket.
- QA correction to `manager-review`: complete triggering `QA Ko`, complete new `Implementation Ready`, complete new `Test Ready`, plus active ticket.

### QA

- Initial QA to `manager-qa`: complete latest `Implementation Ready`, complete `Review Go`, plus active ticket.
- QA correction to `manager-qa`: complete previous `QA Ko`, complete new `Implementation Ready`, complete final `Review Go`, plus active ticket.
- Rejected `Spec Questions` resume to `manager-qa`: complete `Spec Questions`, verbatim PM/user decision, latest complete `Implementation Ready`, latest complete `Review Go`, plus active ticket.
- Accepted `Spec Questions` correction to `manager-qa`: complete accepted `Spec Questions`, verbatim PM/user decision, complete new `Implementation Ready`, complete final `Review Go`, plus replacement ticket.

## Allowed Results

- `manager-po`: `Product Questions`, `Technical Question For manager-dev`, `Feature Spec Ready`, `Design System Intent Required`, or `Blocked`.
- `manager-dev-advice`: `Technical Manager Advice` or `Blocked`.
- `manager-tdd`: `Test Ready` or `Blocked`.
- `manager-dev`: `Implementation Ready` or `Blocked`.
- `manager-review`: `Review Go`, `Review Ko`, or `Blocked`.
- `manager-qa`: `QA Go`, `QA Ko`, `Spec Questions`, or `Blocked`.

Use `scripts/validate-artifact.mjs --role <role>` with the returned artifact on stdin.

## State Transitions

| Current result | Route | Required next result |
|---|---|---|
| `PM Intent` | `manager-po` | author result |
| `Product Questions` | PM/user, then same author | author result |
| `Technical Question For manager-dev` | `manager-dev-advice`, then same author | author result |
| `Design System Intent Required` | stop | Delivery `Awaiting Design System` |
| `Feature Spec Ready` plus ticket | `manager-tdd` | `Test Ready` plus same ticket |
| `Test Ready` plus ticket | `manager-dev` | `Implementation Ready` plus same ticket |
| `Implementation Ready` plus ticket | `manager-review` | `Review Go` or `Review Ko` plus same ticket |
| latest `Implementation Ready` plus `Review Go` plus ticket | `manager-qa` | `QA Go`, `QA Ko`, or `Spec Questions` plus same ticket |
| `Review Ko` | review correction | `Review Go` |
| `QA Ko` | QA correction | `QA Go` |
| `Spec Questions` | PM/user, then rejection resume or accepted spec correction | QA result or corrected `Feature Spec Ready` |
| recoverable `Blocked` | internal recovery | same role result |
| unrecoverable `Blocked` | stop | Delivery `Blocked` |

Return Delivery `Awaiting PM` for `Product Questions`, `Spec Questions`, or unclear PM Intent boundary.

## Corrections

For `Review Ko`:

1. If it contains `manager-tdd` findings, send that owner projection plus latest `Test Ready` and active ticket to `manager-tdd`.
2. Send `manager-dev` findings plus latest `Test Ready` and active ticket to `manager-dev`.
3. Send previous `Review Ko`, latest `Implementation Ready`, latest `Test Ready`, and active ticket to `manager-review`.
4. Repeat until `Review Go`.

For `QA Ko`:

1. Send complete `QA Ko` plus active ticket to `manager-tdd`.
2. Send complete `QA Ko`, new `Test Ready`, and active ticket to `manager-dev`.
3. Send complete `QA Ko`, new `Implementation Ready`, new `Test Ready`, and active ticket to `manager-review`.
4. After `Review Go`, send previous `QA Ko`, new `Implementation Ready`, final `Review Go`, and active ticket to the same `manager-qa`.
5. Repeat until `QA Go`.

For `Spec Questions`, return `Awaiting PM`. Accepted questions go to `manager-po`; rejected questions return to the same `manager-qa`.

## Communication

Use terse state-change lines only:

- `Sent <artifact type> to <role>.`
- `Queued <artifact type> for <role>.`
- `Received <artifact type> from <role>.`
- `Waiting for <role>.`

Do not summarize role discussions for the PM/user.
